## 实现与关键校验

1. 草案候选提供真实策略ID、资料ID、转写版本、规则与证据；组合保存冻结快照，运行再冻结组合版本。重提取或转写编辑使旧source_id不可启动新运行；已经运行中的会话保持冻结策略。空组合、全禁用、未确认/无说明、缺规则、权重不等于100阻止运行；等权/归一化均有显式行为。
2. 没有自然语言自动变均线。原草案待答问题、未支持filter/other规则、缺失止损映射均阻止；其余参数语义由人工核对确认，系统不能证明任意原文与映射完全等价。保留原规则与映射说明供审阅。
3. CSV严格验证有限数、OHLC、日期顺序/重复、已完成日线、主板代码、限价、相邻昨收一致性与规模；正式输入要求证券/公司行为确认。数据不可变、SHA256冻结、演示标签持续保留。
4. 策略只看当前及历史收盘。下一根开盘使用前一根目标仓位，手续费按分四舍五入，买入按100股整手与现金上限；成交保留signal_date/date。按持仓可卖量实施T+1，不卖空；停牌、无量、开盘限价、滑点价越界、超日成交量均拒单。等权或百分比加权实际参与仓位计算，目标分歧可阻止意图；无交易是有效结果。
5. 每个回测/会话独立现金与持仓。账本/游标/请求指纹在SQLite BEGIN IMMEDIATE单事务提交；相同请求或行情不重复消费，同request_id不同操作返回409。已消费行情被修改拒绝覆盖。重启全部paused且保留记录。
6. 回放显式标注；incremental首次仅预热并固定观察日界限，不补撮合该日及更早历史。后续只处理更晚游标；过期行情不推进，断层/不连续昨收报错。轮询15秒，仅服务进程运行时有效。北京时间18:00后才接受当天日线，max_age_days用自然日保守判定；不是精确交易日历。
7. CSV增量通过导入新数据集再sync绑定；Tushare可选服务端TUSHARE_TOKEN，用daily+stk_limit取得未复权日线与官方限价，vol手转股，HTTP超时与脱敏错误；不暴露令牌。能力报告只说明配置存在，外部验证始终false。无券商/真实下单入口。
