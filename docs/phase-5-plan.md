# Phase 5 Implementation Plan

> 执行方法：按用户 AGENTS 的可见聊天工作组并行实施，协调集成，完成后另建可见基本验收聊天。不以后台代理作为可追踪单位。

**Goal:** 完成转写简化、用户本机 API 配置、AI 校正/命名与策略执行参数衔接。
**Architecture:** 沿用本地服务、SQLite和现有组合 DSL；新增独立 AI 配置/协议/校正/映射模块。正文保留原始版本，校正过程可追溯。
**Tech Stack:** Python/FastAPI/SQLite/httpx/Windows DPAPI；原生 HTML/CSS/JS；pytest 与现有 Playwright 工具。
**Spec:** docs/phase-5-design.md。

## Global Constraints

- Key 本机加密保存，只向选定模型供应商用于认证；不写产品云端、日志、导出或浏览器持久存储。
- 转写默认不显示播放器和全文；状态必须反映真实任务阶段，不伪造百分比。
- 原始内容保留，校正不能制造交易条件；规则统一沿用 ma/threshold，保存前用户确认。
- 各组按设计文件边界修改；非 Git 不创建伪造提交或分支；不改正式数据。

## Review Focus

- 下载完成接续 ASR 的瞬间、失败后刷新：不误报完成，重试使用缓存。
- Key 清空、更换供应商/地址、重启：无泄漏，无旧凭据误投递。
- ASR 数字/否定/买卖含义错误：不确定性保留，不能自动变成执行规则。
- 原文/校正版/草案版本变化：证据明确、旧候选不可运行。
- AI 映射途中用户编辑或切换组合：迟到响应不覆盖用户数据；新建议未确认。
