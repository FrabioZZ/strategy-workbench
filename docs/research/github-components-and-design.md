调研日期：2026-11-09。通过 GitHub 搜索、官方仓库 README、skill 内容和许可证核对；没有按星数决定选型，也没有把第三方仓库说明当成执行指令。

## 功能 1 组件

| 官方项目 | 作用 | 本项目接入方式 | 关键限制 |
| --- | --- | --- | --- |
| [yt-dlp](https://github.com/yt-dlp/yt-dlp) | 平台链接解析与媒体获取 | 作为可替换下载适配器，限制支持域名，失败返回上传入口 | [支持列表](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)包含 BiliBili、Douyin，但官方不保证所有链接随时可用；登录、平台改版、访问限制可能导致失败 |
| [faster-whisper](https://github.com/SYSTRAN/faster-whisper) | 本地语音转文字 | 作为 ASR 适配器，保留片段、起止时间；CPU 可使用 int8 | 首次需要模型文件；速度和准确率依硬件、模型、音频而变化，需用实际中文股票视频测试 |

采用小组件组合，避免为功能 1 搬入大型量化平台。服务端 AI 适配器分析转写文本并输出结构化草案，保存来源和依据，用户可复核后导出。模型调用与本地转写分离，可替换供应商。

faster-whisper 源仓库采用 MIT；yt-dlp 源代码采用 Unlicense，预编译包及依赖的许可证需分别检查。当前集成方式以包依赖为主，不把仓库整体复制进项目。[faster-whisper 许可证](https://github.com/SYSTRAN/faster-whisper/blob/master/LICENSE)、[yt-dlp 许可证](https://github.com/yt-dlp/yt-dlp/blob/master/LICENSE)。

**成本判断：** 本地 ASR 不消耗远程大语言模型的 token，但会占用计算资源和模型存储；文本分析仍产生 token 或本地推理开销。因此“更省 token”合理，“必定总成本最低”需要实际视频长度和硬件成本验证。已有可用字幕时，可直接导入文本跳过转写。音频中没有讲到、只在图表或字幕画面展示的信息，需要人工补充或后续加视觉识别。

## 针对本产品的设计步骤

1. **固定主任务与术语。** 用户先回答“这段视频讲了什么可验证规则”；第一版不展示未接入的收益数字或虚假运行状态。
2. **画操作流程。** 导入视频/链接/文本 → 后台转写与状态提示 → 用户校对 → 调用 AI → 逐条核对规则与来源 → 保存/导出。
3. **画低保真布局。** 主区聚焦当前任务；素材历史便于返回；转写和策略依据便于对照。窄屏按任务顺序排列，避免三栏硬挤。
4. **定义设计规范。** 统一中文字号、间距、按钮层级、表单、状态标签；成功、失败、待确认既有文字也有视觉区别，不只靠颜色。
5. **完成真实交互状态。** 包括空白、正在下载、转写中、未配置模型、失败重试、长文本、编辑未保存、证据待确认；保存动作给出反馈。
6. **基本验收。** 完整走主流程，检查键盘操作、窄屏、错误提示和刷新后的数据恢复。用真实能力状态区分“界面可运行”“适配器已接入”“真实端到端验证”。

## 是否需要用户提供草图

不必。现有需求足够做第一版。若用户已有明确想法，提供一张手绘布局或 1–2 个参考软件截图，会减少视觉返工；最有价值的是标出首页最常用的操作、必须同屏的信息和喜欢/不喜欢的部分。无需精确尺寸、配色或专业 Figma 文件。

可用同目录的 `demo-input.srt` 试走字幕导入和编辑流程。这是明确标注的虚构测试输入，不是真实视频、ASR 输出或 AI 提取结果；未配置模型时不能据此声称完成真实 AI 提取。

后续的勾叉与百分比滑条分别控制策略是否启用和组合分配。百分比应明确代表资金分配或信号贡献权重，不能表述为能确定各策略的实际收益贡献。此项不在本期实现范围。
