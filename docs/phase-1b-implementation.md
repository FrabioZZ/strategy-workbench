## 实现结果

- URL 接口的 `url` 字段接受最多10000字符纯链接或完整分享文案；前端为 textarea。服务端只接受唯一的规范 HTTPS B站/抖音单视频或短链；去追踪参数、规范主域名、保留并校验 B站 `p`。多不同链接（包括不同分P）、错误BV格式、恶意域名、凭据、非443端口、非HTTPS、非单视频路径均拒绝。重复的同一规范链接允许。
- 导入链接创建独立 `download` 任务，不检查或调用 ASR/AI。成功持久化缓存与元数据，状态为 `awaiting_transcription`，界面“已获取，待转写”。没有本地 ASR 的上传也先保存，不产生伪造失败任务。
- 新增 `POST /api/documents/{id}/transcribe`。模型配置好后手动读取缓存转写；失败重试仍只读取缓存，不重新下载。缺模型、缺缓存、已有转写或重复活跃任务返回409。SQLite 的活跃任务唯一索引继续做最终并发保护。
- 下载采用现有 yt-dlp 独立实现，先获取信息、拒绝合集/直播/明显超限，再下载单文件并用 PyAV 检查实际音轨、时长与媒体类型。只存选定的安全元数据，不存原始下载URL、headers、cookies 或整份 extractor 数据。
- 保留规范来源 URL 和解析后页面 URL、平台标题、实际时长、平台报告时长、音频/视频类型、字节数、扩展名。默认标题更新为平台标题；用户自定义标题保持。导出增加 `media_metadata`。仅音轨使用 `<audio>`，视频用 `<video>`；类型未确认的历史/本地文件只提供缓存文件链接。
- 固定中文提示区分平台限制、不可用链接、网络/解析、文件大小/时长、媒体解析、转写与提取失败。保留 actual-connect SSRF guard，校验实际IP且对域名连接固定已校验地址，继续覆盖重定向与CDN连接。PyAV本地媒体探测额外限制为file协议，避免原生网络协议绕过Python socket检查。
- 旧 SQLite 数据库自动添加 `media_metadata` 列，不重建/删除原表。原文本校对、提取、来源定位、版本过期保护、JSON 导出保持。
- 未复制/执行 python-spider 旧代码、未调用外部签名服务。未改依赖、下载模型、读取浏览器凭据、登录、绕过付费限制或扩展到整账号/OCR/交易。
